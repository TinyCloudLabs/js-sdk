`tinycloud auth request --preset apps-agent --write --app <app_id>` no longer lets the agent change an app's own code or manifest (TC-1620). KV put is now granted only on `<app_id>/knowledge/` and `<app_id>/prefs/` (the two folders the sample apps' manifests write to), and KV get and list stay on all of `<app_id>/`; SQL read and write are unchanged. A put on `<app_id>/app/` (which holds the code and the stored `app/manifest.json` and `app/install.json`), on the root-level `<app_id>/manifest.json` or `<app_id>/install.json`, or on any other folder is refused by the node. The scope printed to the agent and to the owner says so ("write knowledge and data files ... cannot change the app's code, manifest or install record"; SQL write adds, changes and deletes rows, and creating, changing or dropping tables is granted only on an app's catalog database), and a request file that still asks for a put on the whole app, or on any path outside those folders, is listed under "MORE than the apps-agent preset" and needs the owner's explicit confirmation. Grants issued with the earlier wide write shape keep working until they expire (7 days) or are revoked.
