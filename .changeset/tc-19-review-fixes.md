Review fixes (TC-19): a replica created under an empty `grantSubject` now binds its database to the issuer of the first installed grant (atomically, in `installGrant`); local `get`/`list`/`sync`/`reset`/`setRetentionGrant` are refused to a session that has not presented the bound issuer's grant (`GRANT_UNAUTHORIZED`). A session authorizes only via a grant that would itself install (audience, coverage, bound issuer, in-window) or the grant the database already holds — a refused install never authorizes. Concurrent first opens can no longer race to write two device keys — `deviceIdentity` re-reads inside the write transaction and returns the stored identity — and `init` accepts an identical stored config instead of raising `REPLICA_CONFIG_MISMATCH`. `setRetentionGrant` clears the attested `retainUntil` when the retain grant CID changes (or is cleared), and a committed page only persists `retainUntil` while the stored `retentionGrantCid` still equals the CID the request presented — an in-flight sync cannot revive the previous grant's window. Both affect the SQLite store bundled into `tc replica` and the IndexedDB store. `open()` and `status()` return a restricted status (no key names, etags, counts, grant CIDs or `lastError`) until the session is authorized. `BrowserReplica.close()` rejects in-flight and later calls with `REPLICA_CLOSED` before the close handshake is sent, so a reply arriving mid-close is ignored. Commits broadcast `committed` per page and per repair batch (not only per sync); `reset --purge` and manual `reset` broadcast to sibling tabs, whose stores surface `RESET_REQUIRED` after a sibling purge. **Breaking-ish:** a new browser session must call `installGrant` (same JWT is fine) before local reads or full status on an issuer-bound replica; `REPLICA_CLOSED` replaces `STORAGE_ERROR` for post-close calls.
