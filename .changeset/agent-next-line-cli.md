When `onboard --timeout` or `auth grant --timeout` ends with exit 8 because the owner has not answered yet, stderr now ends with one `Next:` line after the link and the "Still waiting" message. The line opens by saying that the owner cannot see the tool output, then asks the agent to write the link in its reply to the owner before its next tool call and to run the command again in that same reply, without ending the turn or waiting for a reply. In testing agents re-run the command promptly but may relay the link late or not at all, so this is a request, not a guarantee. For a link created in this run it asks for the link to be written before the next tool call; for a resumed wait that reached its deadline it asks for the link to be written first only if it has not been written yet, then for the command to be run again in the same reply. It never claims the owner already has the link. The line names the command as it was run (with the program name `tc` or `tinycloud`) only when every part of the command line is known to be harmless: the subcommand words, a `.json` request file, and the flags `--timeout`, `--profile`, `--host`, `--json`, `--yes`, `--quiet`, `--verbose`, `--no-cache`, `--no-retry`, `--replication` with plain values. For anything else (any other flag, short flags, `--flag=value`, a code or token, a JWT-like or long value, any control character) it says `this same command` and echoes nothing from the command line. When `auth grant` reads its request from stdin (`--stdin`, `--paste`, a bare `-`, or no source) it says `this same command ... again with the same input`, because the command alone would read an empty stdin. stdout (`{"pending":{...}}`) and the exit code are unchanged, and no other exit prints the line.
