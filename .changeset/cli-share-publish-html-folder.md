`tc share publish ./site/` publishes a folder with a top-level `index.html` as one self-contained `.html` page over the anyone-with-the-link path. The folder's stylesheets, scripts, images and fonts are inlined as `<style>`, `<script>` and `data:` URLs by the share-sdk `html-bundle` rewriter (HTML parsed with jsdom, loaded only for a folder publish); the page is named `<folder>.html` or `--name`. A folder the rewriter cannot make self-contained is refused with a typed error that names the file and the offending reference (up to 5 paths, escaped for the terminal): `UNSUPPORTED_HTML` (external URLs, frames, forms, `<base>`, module scripts, links to other pages, ...), `HTML_RESOURCE_MISSING`, `UNSAFE_PATH` (exit 8: `../`, backslashes, control or direction-changing characters, case collisions), `UNSUPPORTED_FOLDER_ENTRY` (symbolic links, special files, nesting deeper than 16), `MAX_BYTES_EXCEEDED` (exit 7), and `INVALID_ARGUMENT` for a folder without a top-level `index.html`. Symbolic links are never followed, including a parent folder swapped for a link while the folder is read (on Linux each file and directory is checked through its open descriptor; on other platforms the checks are best effort and the race is narrowed, not closed); entries starting with `.` are skipped and reported. `manifest.json` and `knowledge/**` are never inlined and are named on stderr; they are not published (sidecar publishing is not available yet). Addressed, `--prefix` and multi-input folder publishing is still refused with `MAX_BYTES_EXCEEDED` (exit 7), now with a message that says folders can only be published as a single page for an anyone-with-the-link share.
