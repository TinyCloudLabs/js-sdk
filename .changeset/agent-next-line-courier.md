Agents are now told, on stderr, to write the link to the owner in their reply and run the next command in that same reply. Each `Next:` line names the exact command in backticks, written as the user ran Courier (`courier` or `tinycloud courier`), and says not to end the turn or wait for a reply. `courier init --request` ends its stderr with a line that says to write the link above in the reply to the owner now and, in that same reply, run `init --wait --timeout 60s`. A pending `courier init --wait` (exit 8) ends with a line that names the same command again (with the words `this same command` and nothing echoed if the command line has a flag whose name suggests a secret, or a value that looks like a one-time code, a long token or a JSON document): for a link created in this run, write the link and run it again in the same reply; for a resumed request, write the link first only if it has not been written yet. A pending `courier invite --wait` ends its stderr, after the existing `[invite-pending]` line, with a line that says to write the invitation link (which stays on stdout) in the reply to the owner now and, in that same reply, run `invite serve <id> --wait 60`. `courier invite serve` prints, at the start of every run, a line with the saved invitation link to write to the owner if it has not been written yet, and, if it ends pending, a last line after `[invite-pending]` that says no one has joined yet and to run the same command again now. A claimed invitation prints no run-again line. stdout JSON and exit codes are unchanged, and other runs print no such line.
