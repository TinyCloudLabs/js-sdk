Courier now prints a `Next:` line on stderr that opens by saying that the owner cannot see the tool output, then asks the agent to write the link in its reply to the owner before its next tool call and to run the next command in that same reply; in testing agents re-run the command promptly but may relay the link late or not at all, so this is a request, not a guarantee. Each `Next:` line names its command in backticks, written as the user ran Courier (`courier` or `tinycloud courier`), and says not to end the turn or wait for a reply. `courier init --request` ends its stderr with a line that asks for the link above to be written to the owner and `init --wait --timeout 60s` to be run in the same reply. A pending `courier init --wait` (exit 8) ends with a line that names the same command again (only when every part of the command line is a known `init --wait` flag with a plain value; otherwise the words `this same command` and nothing from the command line, including any control character, is echoed): for a link created in this run, write the link and run it again in the same reply; for a resumed request, write the link first only if it has not been written yet. A pending `courier invite --wait` ends its stderr, after the existing `[invite-pending]` line, with a line that asks for the invitation link (which stays on stdout) to be written to the owner before the next tool call and `invite serve <id> --wait 60` to be run in the same reply. `courier invite serve` prints, at the start of every run of a live, unclaimed invitation (not an expired or already-claimed one), a line with the saved invitation link to write to the owner if it has not been written yet, and, if it ends pending, a last line after `[invite-pending]` that says no one has joined yet and to run the same command again now. A claimed invitation prints no run-again line. stdout JSON and exit codes are unchanged, and other runs print no such line.
