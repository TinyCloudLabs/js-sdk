The standalone `courier` command now updates itself. Each time a process starts (a `courier watch` service restart counts; a watcher that keeps running does not re-check), at most once every 24 hours per install, it reads npm's `latest` dist-tag. If that is a stable release newer than the running one, it installs it with npm, globally or in the app directory where Courier was installed, then runs the same command on the new version. It never downgrades and never follows `beta`, `next` or a prerelease on `latest`. pnpm, yarn and bun installs are not updated (the log line gives the command to run).

Before switching it downloads the tarball into a private directory while hashing it (sha512 must equal the registry's `dist.integrity`), verifies the release's npm provenance with sigstore (signature, Fulcio certificate chain, Rekor inclusion) with the signer pinned, as an anchored exact match, to this repository's `changesets.yml` workflow on `refs/heads/master` and the signed statement naming the file it hashed, and runs `npm audit signatures` on a staged install of that file. Then it installs that same file, not a name and version fetched again, with install scripts off, the registry named explicitly, npm's user and global configuration ignored and `npm_config_*` and `COREPACK_*` removed from the environment. A release that fails a check, or has no provenance, is not installed. A failed install is rolled back to the running version's registry tarball (hash checked); if that fails too the command does not run when no usable copy is left. A skip is one line on stderr and never fails the command: registry unreachable, no write permission to the install or its bin directory, under CI, a pnpm, yarn or bun install, Windows (auto-update is off there), or a woken agent's own `courier` calls (they now carry `COURIER_WAKE_CHILD=1`). `npx`, `pnpm dlx`, `bunx` and `yarn dlx` runs and source checkouts are never updated. The 24 h check is recorded per install. Each step has a hard time limit; the worst case for one start is 118 s. Courier's own dependencies are resolved from the registry at install time and are not covered by these checks. Set `COURIER_NO_AUTO_UPDATE=1` or pass `--no-auto-update` to pin the version; `tinycloud courier` is not affected. Details are in the README's "Updates" section.

`@tinycloud/courier` now depends on `sigstore` 3.1.0 (exact pin, loaded only when an update is being verified).
