`tc auth login --paste`, `tc auth rotate --paste` (on a profile without named keys), `tc init --paste` and `tc auth request --grant --paste` (custom `--cap`, `--permission` and `--manifest` grants) now let you choose the session lifetime on the OpenKey page: their link carries `expiryChangeable=true`, so a lifetime longer than `--expiry` can be signed. The CLI saves the lifetime that was signed, however long: there is no upper bound. It refuses only a signed lifetime of 60 seconds or less (`OPENKEY_EXPIRY_TOO_SHORT`) or one that has already ended (`AUTH_EXPIRED`). A paste login no longer refuses before approval because `--expiry` is shorter than a live session; the check runs again on the signed lifetime when the login is saved. Signed approval requests, device login, `tc onboard` (including a pasted code) and the prepared replica and `--keys` logins never send the opt-in and keep the `--expiry` ceiling; that includes `tc auth login --paste` with `--keys` or replication prefixes, and `tc auth rotate --paste` on a profile that has named keys (it uses the prepared login).

`tc auth request --grant --preset apps-agent --paste` does not send the opt-in: agent presets keep the 7-day agent policy, so the lifetime can be shortened on the OpenKey page but not extended, and custom `--cap`, `--permission` and `--manifest` grants are the ones that can choose longer.

A long paste session makes a later, shorter scoped login on the same profile ask for `--replace-session`. That is the existing policy for replacing a live session with a shorter one, and the error message names the flag.

When `tc auth login --paste`, `tc init --paste` or `tc auth rotate --paste` refuses the approval it was given (a signed lifetime of 60 seconds or less, a wrong owner, an expired or invalid proof, a scope that does not match), OpenKey has already granted it, bound to the profile's key, and the CLI cannot revoke it itself (a login's approval carries no revoke ability). The CLI now deletes the saved copy of the pasted code, deletes the profile's key when this sign-in created it (a profile this login created, or a rotation) so the grant cannot be used, removes a profile that this login created, and prints one line: OpenKey granted this approval until its date, this CLI did not use it, its key was deleted, and you can also remove it at account.tinycloud.xyz. A key that already existed is kept, because other grants or sessions may use it: the line then says the grant is live until its date and the key still exists on this device, and to revoke it at account.tinycloud.xyz. The exit code is unchanged. A login that succeeds is unchanged.
