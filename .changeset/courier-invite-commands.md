Add `courier invite <handle>`, `courier invite list`, `courier invite revoke <invite-id>`, `courier join <invite-string>` and `courier join --resume`.

- `invite` creates a one-time invite for a handle and email address and prints the invite string once. `invite list` shows metadata only. `invite revoke` deletes the sealed invite and any pending hello or welcome.
- `--tier` is the requested tier. `--tier trusted` asks for trusted status; the paired peer starts strict until the owner confirms by hand. Self-service invites never create a trusted peer.
- `--expect-owner <did>` (a `did:pkh:eip155` DID) records the account the invitee must pair from; a hello from another owner is held with reason `owner-mismatch`.
- `watch` verifies the email credential in each hello: it is signed by the pinned issuer, names the invited address, was issued within the last hour, is bound to the invite's one-time key and has not been used for this invite before. Its subject and the possession proof must also be the courier DID in the hello's pairing artifact, otherwise the hello is held with reason `holder-mismatch`. A hello that passes pairs the peer as strict; `--also-ask` holds it for `invite approve` even then.
- With `--invites-public-dir <dir>` or `COURIER_INVITES_PUBLIC_DIR`, `invite` also writes a non-secret copy of the invite record (`<invite-id>.json`, mode 0640) and `invite revoke` updates its status. The copy holds no keys, tokens or blob ids.
- `join` reads the invite string from `--stdin` or `--file`; the positional form also works but is visible in `ps`. It sends a hello with an optional credential from `--credential-file` or `--credential-stdin`, and waits about 10 minutes for the owner's reply. `join --resume` continues a pending join without sending a second hello.
- Handles may not begin with `_`. Stored peers whose handle begins with `_` are excluded from notice tracking in `watch`.
- The words `list` and `revoke` cannot be invitee handles, because they select `invite` subcommands.
- Revoking an invite does not revoke delegations granted to its one-time key. Those end at their TTL.
- `watch` checks each incoming hello. A hello that fails a check, or whose pairing cannot finish, leaves the invite held and emits an `invite-held` notice. A held invite is not complete: `invite approve` or `invite deny` it. A failed write to the public copy does not change the pairing; the reason code is logged and the next sweep rewrites the public `status` and `completedPeer` from the private record.
- An invite left `consumed` by a crash is recovered on watch startup and on each sweep, once it is at least 10 minutes old. If its hello is still present and valid it is held with reason `internal-error` (one `invite-held` notice). If the hello is gone or invalid it is marked `failed` with reason `hello-lost` (one `invite-failed` notice) and closes at its expiry.
- `invite approve <invite-id> [--tier strict|trusted]` completes a held invite: it pairs the peer, writes one Welcome and marks the invite completed. `--tier trusted` records a trusted request; the peer starts as strict until you confirm trusted status. Retrying `approve` after a failure completes the same pairing without a second Welcome.
- `invite deny <invite-id>` rejects a held invite, writes a rejected Welcome and drops the pending peer.
- `invite`, `invite approve` and `watch` refuse a handle that has an entry in the box's `peers.json` (`<COURIER_HOME>/peers.json`, `<COURIER_HOME>/intake/peers.json`, and the file named by `--peers-file` or, without the flag, `COURIER_PEERS_FILE`), so a new peer never inherits an old entry's trust. `--peers-file` replaces `COURIER_PEERS_FILE` for that command. The named path must be absolute, free of control characters and exist; an empty value, a relative path or a missing file stops the command with an error. Every value `watch --install-systemd` writes into the unit goes through one of two writers: quoted words (`ExecStart=` arguments, `Environment=` assignments) escape backslash, quotes, `%`, newline, carriage return and tab (and `$` in `ExecStart=`) and refuse other control characters; the path directives (`WorkingDirectory=`, `StandardOutput=`, `StandardError=`) refuse control characters, relative paths and a trailing backslash or whitespace, and double `%`. Environment names must be plain variable names. `watch --install-systemd` checks it and writes `COURIER_PEERS_FILE` into the unit. `invite` fails with `peers-entry-exists`; `watch` holds the hello with that reason; `approve` fails with it and the invite stays held. A peers file that exists but is not a readable JSON object, or a named file that has gone missing, refuses with `peers-unreadable`. Remove the entry to continue.
- On every poll `watch` also looks for a hello on each open invite, so a hello written while the watcher was not subscribed is still handled. The hello is consumed first, so it pairs once.
- If `join` finds a hello already stored for the invite that is not the one it wrote (or that it cannot read back), it does not write over it. It polls `out/welcome.json` and pairs only with a Welcome addressed to this courier from the inviter pinned when the invite was accepted. If none arrives before the invite expires (or only Welcomes that do not verify for this courier, which it says with a stable code) it stops with `hello-exists`, also on a `join --resume` after expiry, and says to ask the inviter for a new invite (and to run `courier revoke <handle>` first if that is refused with "already exists"). `join --resume` re-enters the wait and never writes again.
- A new invite from the same inviter replaces the unfinished pairing an earlier failed `join` left behind and drops that join's state. A paired peer under the handle still blocks. `invite revoke` frees a handle whose pairing never started.
- `invite approve` prints the tier the invite carries.
