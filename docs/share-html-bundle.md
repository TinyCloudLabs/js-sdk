# HTML folder bundling (`@tinycloud/share-sdk/html-bundle`)

The rewriter that turns a folder (a root `index.html` and the files it uses) into pages that are self-contained (defined below). It is the source of truth for what an HTML artifact folder may contain. Consumers: `tc share publish ./site/` (one self-contained `.html`, published over the bearer path) and the Share web composer (folder detection and path rules).

It is a subpath, not part of the package root, so browser bundles that import `@tinycloud/share-sdk` do not carry it.

## What "self-contained" means

The guarantee is exactly what the final check enforces, nothing more. At render time the finished page holds no reference that fetches or navigates anywhere except `data:` URLs the rewriter wrote and `#fragment`s of the page itself. External URLs, relative paths, links to other pages and links out are refused (or, for the rewriter's own inputs, inlined), not passed through.

`assertSelfContainedPage(page)` is that check. It reads the finished page (its own `data:` URLs cut out first) twice, by a byte-level scan with its own tokenizer and by the DOM parser, and refuses the page (`unsupported`) if any of these hold:

- **URL-bearing attributes.** `href` (any element: `<a>`, SVG `<use>`, `<image>`, `<feImage>`, `<mpath>`, MathML), `xlink:href`, `src`, `srcset`, `imagesrcset`, `poster`, `action`, `formaction`, `ping`, `attributionsrc`, `background`, `cite`, `data`, `codebase`, `archive`, `classid`, `profile`, `longdesc`, `usemap`, `manifest`, `icon`, `lowsrc`, `dynsrc`, `itemtype`, `itemid`: the value, read as a browser reads it, must be `data:;base64,...` (the rewriter's own form) or `#` followed by printable characters. Reading means: entities decoded (`&nbsp;`, `&#x..;`, `&Tab;`, `&NewLine;`), tabs and newlines removed, leading and trailing controls and spaces trimmed, and nothing else trimmed (U+00A0 and other Unicode whitespace stay, so `&nbsp;#c` is a relative path and is refused). A relative path (`evil.png`), an empty or valueless attribute, a scheme, `//host` and a backslash host (`\\host/x`) are all refused. `ping` is refused whatever it holds. A `srcset` is checked candidate by candidate.
- **Other attributes.** Outside a text allow-list (`alt`, `title`, `placeholder`, `value`, `label`, `content`, `name`, `id`, `class`, `lang`, `summary`, `abbr`, `datetime`, `pattern`, `xmlns*`, `aria-*`, `data-*`), an attribute whose value reads as a URL (a network or script scheme, `//host`, `\\host`, a path) is refused whatever its name. Allow-listed attributes may hold any text. `on*` attributes are refused.
- **CSS** in `<style>` and in every `style` attribute (and any other attribute that holds `url(`, such as an SVG presentation attribute): no `@import`, `image-set()` or `src()`, and every `url()` is a `data:` URL or a `#fragment`, with backslash escapes in the names decoded first and CSS whitespace (not U+00A0) around the value.
- **`<meta http-equiv>`.** The only one allowed is the rewriter's own Content-Security-Policy, with exactly its content. `refresh`, `Link`, `Set-Cookie`, `Default-Style`, an author policy and every other `http-equiv` are refused (the rewriter drops all author ones before this check).
- **Elements.** `<base>`, `<form>`, `<iframe>`, `<frame>`, `<frameset>`, `<object>`, `<embed>`, `<applet>`, `<portal>`, `<noscript>`, `<xmp>`, `<plaintext>`, `<noembed>`, `<noframes>`, `<area href>`, a `<link>` without `href`, a `<script src>`, and (by the DOM pass, which knows the namespace) an SVG `<script>`.

What it does not enforce: what a page's own script does, and text that is not an attribute or `<style>` (a script or a text node may hold `https://` as data). Scripts are scanned for a list of blocked capabilities when they are rewritten, and the viewer's sandbox (`sandbox="allow-scripts"`, an opaque origin) and its Content-Security-Policy are the second line for everything a script can do and for anything this check cannot see. A name that is not on any list here and whose value is not URL-shaped is not treated as a reference.

## API

- `prepareHtmlArtifact(files, { parseHtml?, singlePage? })`: every `.html` page of the bundle, rewritten. `files` are `{ path, bytes, mediaType? }` with `/`-separated paths relative to the folder. Without `parseHtml` the browser's `DOMParser` is used; elsewhere pass an HTML5 parser (the CLI passes jsdom's, built on parse5, so the rewriter sees the tree a browser builds). `singlePage: true` transforms only `index.html` and refuses links to other pages.
- `inlineHtmlFolder(files, { parseHtml? })`: `prepareHtmlArtifact` with `singlePage`, returned as `{ html, passive, fileCount, sourceBytes }`.
- `assertSelfContainedPage(page, { parseHtml? })`: the final check described above, on any finished page. `prepareHtmlArtifact` runs it on every page it writes.
- `canonicalArtifactPath`, `resolveArtifactReference`, `detectHtmlArtifact`, `artifactMediaType`, and the limits (`MAX_ARTIFACT_*`).
- `ArtifactBundleError { kind: "malformed" | "missing" | "unsupported" | "limit", path?, reference? }`. `path` is the bundle file being processed and `reference` the reference text that was refused; both are untrusted text from the folder, so escape them before printing.

## Rules (anything else is refused, never passed through)

- Every reference is resolved inside the folder: no `../` out of it, no absolute or protocol-relative URL, no scheme (`http:`, `data:`, `javascript:`, `mailto:`), no backslash, no percent-encoded `/`, `\` or `.`, no control or direction-changing code point. Names are NFC-normalized; two names equal after lowercasing collide; lookups are case-sensitive. A query string or fragment on a reference is ignored for the lookup.
- Inlined: `<link rel=stylesheet>` (with `media`), `<link rel=icon>`, `<style>`, `style=""`, CSS `@import` and `url()` (bounded depth, cycles refused; an imported stylesheet can only hold rules: one that uses `url()` is refused, so put images and fonts in the page's own stylesheet or `<style>`), classic `<script src>`, `img`/`source`/`video`/`audio`/`track`/`input[type=image]` sources, `poster`, `srcset`.
- Refused: `<noscript>` (a parser with scripting off and the viewer's frame read it differently), `<xmp>`, `<plaintext>`, `<noembed>`, `<noframes>`, a `<script>` inside inline SVG (a browser reads its content as markup, not script text), `<area href>`, any `ping` attribute, a `<link>` without `href`, `<base>`, `<form>`, `<iframe>`, `<frame>`, `<frameset>`, `<object>`, `<embed>`, `<portal>`, event-handler attributes, module/`async`/`defer` scripts, scripts that call `fetch`, `XMLHttpRequest`, `WebSocket`, `EventSource`, workers, `sendBeacon`, `window.open`, `location`, dynamic `import()`, `eval`, `WebAssembly`; any `<link rel>` other than stylesheet and icon (`preload`, `prefetch`, `preconnect`, ...); inline SVG elements with an `href` / `xlink:href` that is not a `#fragment`, SVG animation of an `href`, SVG attributes (`fill`, `filter`, `mask`, `style`, ...) with a `url()` that is not a `#fragment`; CSS `image-set()`, `src()` and an `@import` that is not inlined; CSS backslash escapes in `url`, `@import`, `image-set` and `src` are decoded before this is checked; a link to anything but a page in the folder (and, with `singlePage`, to any other page).
- `<template>` content (including declarative shadow roots) is examined and rewritten like the rest of the page.
- Dropped: every author `<meta http-equiv>` (`refresh`, `Link`, `Set-Cookie`, an author Content-Security-Policy, `X-UA-Compatible`, ...). The output carries its own strict CSP meta and no other.
- Limits: 1,000 files, 100 MiB of source, 10 MiB per inlined resource and for the rendered output, 5 MiB per text file, 2,000 references, CSS import depth 16. The inlined bytes are counted per reference, against the 10 MiB output cap, as they are added: a page that refers to one large file many times is refused at the reference that passes the cap (`limit`), before the copy is built.
- An SVG file referenced from `<img>` or CSS becomes an `image/svg+xml` data URL: it is an image there, so its own scripts and external references do not run or load.

## Passive files (the extension point for artifact-to-app, T8)

`manifest.json` at the root and anything under `knowledge/` (case-insensitive, by canonical path) are passive: `inlineHtmlFolder` never inlines them, never lets the page reference one (the reference is refused as missing), does not parse them, and returns them unchanged and sorted in `passive`. They still count against the file and source limits. The function only separates them; a publisher that can store sidecar files next to the page takes `passive` from the result. `tc share publish` has no sidecar transport yet: it names them on stderr and does not publish them.

## CLI notes

The CLI reads the folder itself: symbolic links and special files are refused (never followed or read), entries starting with `.` are skipped and reported, nesting deeper than 16 folders is refused, and a file is read through a descriptor opened without following links and bounded by the byte limit.

A folder that another process changes while it is published (a subfolder swapped for a link to somewhere else) is a race the CLI narrows differently by platform:
- **Linux: every step is checked on the descriptor.** After a file or directory is opened, the real path of the open descriptor (`/proc/self/fd/<fd>`) must be exactly its path inside the folder's real path, and a directory is listed from its descriptor, so the path is not looked up again. The proof is the step-by-step tests (`src/share/html-folder.test.ts`), which put a swap at each exact point (before the `lstat`, between the `lstat` and the open, after the open, after the descriptor check, after the read) and show the outside file is refused at each. A test with a real process swapping a subfolder and a link in a loop runs as a smoke only: its window is far too narrow for thousands of walks to find (the earlier path-based check, which did leak, also passes it), so a clean run of it is not evidence.
- **Elsewhere (macOS): best effort.** Node cannot ask a descriptor where it lives (no `F_GETPATH`, no `openat`), so the checks are the strongest available: the path must resolve to itself, be the opened file (same device and inode), and after the read every parent directory and the file are checked again. That narrows the window but does not close it: a process that can write to the folder during the publish and times its swaps can still win.

The precondition either way is another process with write access to the folder while it is published. Hard links to outside files are indistinguishable from files and are read. Echoed paths and references are escaped (`\u{..}`) and clipped.

A folder is published only to an anyone-with-the-link target. For an addressed target, `--prefix`, or a folder next to other inputs the CLI refuses with `MAX_BYTES_EXCEEDED` (exit 7, the code a directory has always had) and a message that says folders need `--to anyone`.
